提出 ClarifyGPT 框架，讓 LLM 在寫程式前先判斷需求是否模糊，若模糊就主動向使用者提出針對性的澄清問題，取得回答後再改寫需求並重新生成程式碼。

- 方法（三個階段）
  - **需求模糊偵測（two-step code consistency check）**核心觀察是：需求清楚時，LLM 取樣出的多份程式碼行為會一致（相同輸入得到相同輸出）；需求不清楚時，多份程式碼行為會分歧。第一步用 type-aware mutation 生成大量高品質測試輸入，第二步對同一需求取樣 n 份程式解，比對其在這些輸入上的行為是否一致。
  - 生成澄清問題：判定為模糊時，提示 LLM 產生針對性問題（採用類 CoT 的推理式提示，先分析分歧原因再提問）。
  - 需求精煉與重新生成：把使用者回答併入原需求，輸入同一個 LLM 產生最終程式碼。
  - 另外提出高擬真使用者回應模擬方法，讓評估能在不需真人參與下大規模自動化執行。
- 結果與值得參考的結論
  - 十位受試者的人工評估中，GPT-4 在 MBPP-sanitized 的 Pass@1 由 70.96% 提升到 80.80%。
  - 自動化評估下，GPT-4 與 ChatGPT 在五個 benchmark 的平均表現分別從 62.43% 提升至 69.60%，ChatGPT 亦有顯著提升。
  - 可參考的點：
    - 「多次取樣結果的行為一致性」可當作偵測需求模糊度的訊號，不需額外訓練或標註。
    - 只在偵測到模糊時才提問，避免對清楚需求做無謂互動。
    - 用 LLM 模擬使用者回應，是互動式系統評估規模化的可行做法。
